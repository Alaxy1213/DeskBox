DeskBox —— 桌面整理盒子
==================================================

免安装，双击 DeskBox.exe 就能用。
依赖：.NET Framework 4.8（Windows 10 / 11 自带；Win7 / 8 需要先装 4.8）。
不需要管理员权限，不写系统目录，所有数据都在本文件夹里。


一、怎么用
--------------------------------------------------
· 启动后桌面出现一个半透明盒子，盒子里有标签（也就是子盒子）。
· 把桌面上的图标 / 文件拖进盒子 = 剪切：
  文件会真的移动到本目录 items\盒子名\标签名\ 下面，桌面上那个就没了。
  所以盒子里的图标指向的是本程序自己的文件，不是快捷方式。
  拖到盒子上会出现一条插入位置指示线（有反馈才说明盒子收到了）；
  桌面快捷方式、跨盘拖入这类只给"复制/链接"的拖拽也能放进来。
· 双击盒子里的图标 = 打开；按住左键拖出方框可框选，Ctrl+点击可多选。
· 拖动图标可换位置；拖到别的标签或别的盒子 = 把文件移过去。
· 把盒子里的图标拖出去也能用：拖到桌面 / 资源管理器 = 剪切过去（文件真的搬走，
  盒子里的条目自动消失）；按住 Ctrl 拖 = 复制过去（条目保留）。
  拖到网页的上传框（网盘、相册、B 站投稿等）= 直接把盒子里的文件上传上去。
  拖动时会有一个半透明的小方块跟着鼠标，被拖的图标在盒子里变淡虚线框，看得见在搬东西。
· 拖出去之后盒子里的图标会自动消失（目标端真的把文件搬走了才会消失；
  只是复制 / 上传的话图标保留）。万一某个图标还是留着，右键它选
  "从盒子里移除（文件已不在，只清图标）"就能清掉。
· 图标走和资源管理器**完全相同**的系统图标接口，按实际显示尺寸（48px）取图：
  shell 会从图标资源里最大的一张（通常 256px）高质量缩到 48px，而不是直接贴
  .ico 里那张硬边 48px 小图，所以边缘和桌面 / 资源管理器一样细腻，不会发糊。
  实测两者像素级一致。
· 右键菜单不再等系统的右键扩展，弹出来是瞬时的（构建 0ms）。
· 切标签不再有"卡一下"：图标在启动后由后台按 25ms/个 逐个预取，
  预取尺寸与实际显示尺寸一致，缓存能真正命中，切到很少打开的标签也是即时的。
· 右键图标：固定的 8 项菜单（打开 / 打开文件所在的位置 / 以管理员身份运行 /
  剪切 / 复制 / 创建快捷方式 / 删除 / 属性）。
  "打开文件所在的位置"对快捷方式会定位到它**指向的目标**所在文件夹，
  而不是 .lnk 文件自己（死链接或网址快捷方式则退回定位快捷方式本身）。
  这一版**不再调用系统的右键扩展**（WinRAR、网盘、手机助手那些），
  所以右键是瞬时的（菜单构建 0ms）——代价是这些扩展项不显示了。
· Shift + 右键图标：DeskBox 自己的功能（打开所选、重命名显示名、
  搬进当前子盒子文件夹、从盒子里移除 / 放回桌面、在资源管理器中定位、
  移动到其他标签）。不按 Shift 就是上面那 8 项，互不干扰。
· 右键盒子标题栏（共 10 项，增删排在最上面一组）：
    新建盒子 / 新建子盒子 / 重命名子盒子 / 删除盒子 / 删除子盒子   ← 增删成对挨在一起
    ────
    配色主题 ▸ / 盒子颜色 ▸
    配色…            ← 打开配色面板，四层分别调颜色和透明度
    ────
    开机自动启动（打勾表示已开启）
    ────
    退出 DeskBox
  只剩一个子盒子时「删除子盒子」是灰的。
  「配色主题」是 5 套底板（赛博 / 马卡龙 / 莫兰迪 / 莫兰迪-深 / 黑白），
  「盒子颜色」是当前主题下的 5 支强调色（带色点，点了立刻生效并存盘）。
  强调色只用在标题左色条、选中标签下划线、选中框和锁图标上，
  标题和文件名永远用主题文字色——彩色字在花壁纸上读不清。
  锁 / 解锁 = 点标题栏右边那把锁。
· 改名是**就地**的，不弹输入框：双击标题栏改盒子名，右键菜单「重命名子盒子」
  或按 F2 改当前标签名，选中一个图标按 F2（或 Shift+右键→重命名显示名）改显示名。
  输入框正好盖在原来那行字上，背景色从屏幕上取，看着就是原地变成可编辑；
  回车 / 点别处 = 保存，Esc = 取消，中文输入法正常可用。
  切标签不会再误触发改名（以前双击标签就跳重命名，手快点两下就中招）。
· 右下角托盘图标：显示/隐藏全部盒子、新建盒子、退出。
· 盒子固定在桌面上：不进 Alt+Tab、不在任务栏占位、也不会浮到其它程序上面
  （被程序窗口盖住就是盖住，不会跟着抢前台）。
· 打开新程序、切换窗口时盒子不会再闪：只有“桌面独占屏幕”（Win+D 把所有窗口
  最小化）才允许临时浮到桌面图标层之上，其余时间一律留在桌面那一层不动。
· 任务栏点“显示桌面”或按 Win+D 时，盒子仍然留在桌面上；
  点回任意程序窗口，盒子就在程序后面（它一直贴着桌面那一层，不会浮上来挡屏幕）。
· 点任务栏**右下角「显示桌面」按钮**时盒子不会再闪：判据对任务栏提示 / Peek
  残留窗口留了容差，并把「桌面独占」收敛成一个稳定状态，浮起 / 沉底都只读这
  同一个状态，不会因为一两个瞬时采样点就一沉一浮来回翻。
· 拖动盒子靠近屏幕边缘或其它盒子时会自动吸附对齐。


二、目录里都是什么
--------------------------------------------------
DeskBox.exe         程序本体
deskbox.json        盒子 / 标签 / 条目的配置
items\              盒子里那些文件的本体（每个盒子一个文件夹，子盒子是子文件夹）
deskbox-tray.ico    托盘图标（程序自动生成）
deskbox.log         运行日志（出问题时看这个）
startup-report.txt  用 --startup 修正开机启动时生成的记录（可选）
health-report.txt   启动体检报告：只有盒子里的条目文件找不到时才会生成，
                    里面逐条列出丢了哪些（把它们重新拖回盒子即可，别的不用管）

换电脑、换目录：把整个文件夹一起拷走就行，程序会自己把条目路径接回来
（日志里出现 rebase 记录说明做过自愈）。只拷 DeskBox.exe 会丢配置和文件。


三、常见问题
--------------------------------------------------
1) 拖文件进盒子提示"访问被拒绝"
   多半是安全软件在保护桌面目录。把本文件夹和桌面加入白名单后再试；
   程序不会因为失败而丢条目，源文件也会保留。

2) 换了位置后，开机启动还指向老路径
   在本目录执行一次：DeskBox.exe --startup
   （只在原本已开启开机启动时才会改写注册表，结果写在 startup-report.txt）

3) 想恢复成默认状态
   关掉程序，删除 deskbox.json（下次启动会重建一个默认盒子）。
   items 里的文件请先自己搬出来再删 —— 程序不会自动删除任何文件。

4) 盒子太透 / 太实，想单独改背景 / 边框 / 字的颜色
   右键盒子标题栏 → 配色…，打开配色面板。盒子外观拆成四层，每层一行：
     背景    盒子的底板
     边缘线  外面那圈描边（还有个 1/2/3 的粗细）
     文字    标题、标签、文件名
     分隔线  标签栏下面那条细线（0% 就是不画这条线）
   每层都能单独设颜色和透明度（0=完全透明，100=完全实心），
   勾上「跟随」就是不用自定义、继续吃当前主题的那一层。
   下面 7×7 的调色板点一下立刻作用到盒子上，「更多颜色…」开系统取色器。
   最下面还有「圆角」滑块（0=方角，28=很圆）。
   「保存」只写当前这个盒子；「应用到全部盒子」把这一套推到所有盒子；
   「恢复跟随主题」把四层和圆角都退回主题默认；「取消」（或按 Esc）全部还原。
   改的时候盒子上是实时预览的，不用反复开关面板。
   想整体换风格还是先用「配色主题」——那是成套调好的，别一个个手调。


四、维护参数（高级）
--------------------------------------------------
DeskBox.exe --migrate    无界面整理旧版数据，结果写 migrate-report.txt
DeskBox.exe --startup    修正开机启动注册表路径（换目录后用）
DeskBox.exe --icons 输出.png <文件或文件夹...>
                         把条目图标渲染成图片，用来核对图标效果
DeskBox.exe --probe      只读：判断当前是“显示桌面”还是“有程序窗口”，
                         结果写 probe-report.txt（1=桌面独显 2=有程序窗口）
DeskBox.exe --watchtest  自测“显示桌面”时的表现：程序自己按一次显示桌面，
                         逐帧记录盒子有没有来回闪，结果写 watchtest-report.txt，
                         同时截一张 watchtest-shot.png（期间会自动把最小化的窗口复原）
DeskBox.exe --noauto     配合 --watchtest 用：关掉守护纠错，只做观察
DeskBox.exe --render 输出.png [盒子序号|all]
                         离线出图：按当前配置把盒子界面 1:1 画成 PNG，不显示桌面、
                         不截屏。可加 --theme 0..4 看各套配色、--step 0..5 看底板不透明
                         度档位、--plate 0.8 直接指定底板不透明度（0~1）做比档。
                         同时会输出 -onbg.png（压在模拟壁纸上）和 -zoom.png（2 倍特写）
DeskBox.exe --shot 输出.png
                         截全屏（半尺寸），并把每个盒子所在区域 1:1 切成 输出-box0.png 等
DeskBox.exe --menutest [--win]
                        弹一次盒子右键菜单，然后按 z 序核对菜单有没有被盒子自己盖住，
                        结果写 menutest-report.txt（加 --win 会先把盒子顶成 topmost 再测，
                        也就是"刚按过显示桌面"那一刻的处境）
DeskBox.exe --deskmenu [秒数] [desktop|taskbar]
                        复现"显示桌面状态下右键桌面，盒子持续闪烁"：显示桌面 → 右键桌面
                        图标层弹出壳自己的菜单 → 每 40ms 数盒子 topmost 翻了几次，
                        结果写 deskmenu-report.txt。判定标准：翻转次数=0 才算正常
                        （本机 Win11 25H2 实测：修复前 4 秒翻 15 次，修复后 0 次）
                        不加参数=右键桌面；加 taskbar=右键任务栏（另一条触发路径）
DeskBox.exe --wins      正常启动一次，1.5 秒后把每个盒子的几何写进 wins-report.txt
                        再退出。用来核对"重启后盒子有没有跑位"：
                        cfg（配置里的 X,Y）应当等于 winRect（真实窗口矩形）起点，
                        同时打印 client / clientOrg / style，能看出客户区与窗口原点的偏差
DeskBox.exe --geomlog    把每次启动的几何中间态（ctor / handleCreated / apply#N）
                        全打进 deskbox.log。平时日志里只有每个盒子一条 shown-end，
                        怀疑"位置又偏了"时加这个参数看全过程
DeskBox.exe --shellmenu  对盒子里第一个真实条目弹一次原生 Windows 菜单，
                        连续采样"菜单 z 序 / 盒子 z 序 / 重叠区像素"写 deskbox.log，
                        再截一张 shellmenu-shot.png 后关掉菜单退出。
                        判据：菜单 z 序 < 盒子 z 序，且重叠区像素是亮的（菜单在上面）
DeskBox.exe --shellmenucmd
                        按动词名直接调一次 shell 命令（copy，不弹窗），
                        然后检查剪贴板里有没有出现这个文件，结果写 shellmenucmd-report.txt。
                        用来验证"菜单点了之后真的会执行"
DeskBox.exe --styleform 打开「配色」面板并截图后退出：背景 / 边缘线 / 文字 / 分隔线
                        四层各截一张（styleform-shot.png / -1 / -2 / -3），用来核对
                        自绘控件有没有错位、漏画
DeskBox.exe --stylesave 走一遍"改样式 → 保存 → 重新读配置"，逐项比对 DStyle 有没有
                        真的落进 deskbox.json，结果打在日志里（PASS/FAIL）。
                        注意：这个开关会改配置，跑前先备份、跑完还原
DeskBox.exe --dragtest  不开拖拽，只把"真要交给系统的拖拽数据"列出来：
                        必须有 FileDrop（资源管理器/浏览器上传都靠它），
                        PreferredDropEffect 默认 2（剪切）、按 Ctrl 时 1（复制），
                        结果写 dragtest-report.txt
DeskBox.exe --perftest  体检"切标签慢 / 右键慢"：切标签渲染计时（连做三轮看冷热）、
                        图标缓存命中数、单独构建一次 shell 菜单的各步耗时，
                        结果写 perftest-report.txt
DeskBox.exe --prunetest 验证"拖出去后图标残留"：造一个临时条目并删掉文件，
                        走真实的拖后校验流程，1.5 秒后核对条目和 deskbox.json
                        是否都清干净了，结果写 prunetest-report.txt
DeskBox.exe --boxmenu    弹一次盒子菜单并展开「盒子颜色」子菜单，把菜单连同盒子
                        截成 boxmenu-shot.png，同时往日志里逐条打印子项（名字 / 色点
                        位图在不在 / 哪个是打勾项）。用来核对色点真的画出来了、
                        子菜单没被盒子自己盖住
DeskBox.exe --renametest [0|1|2|3|4]
                        就地改名自测：0=盒子标题 1=标签 2=图标名，弹出编辑框后
                        连盒子一起截成 rename-shot-N.png；3 / 4 是真提交一遍
                        （标签 / 图标），打日志验证真的落进配置。会改配置，跑前备份
DeskBox.exe --droptest 只跑拖放效果的判定（不搬文件、不改配置），报告写
                        droptest-report.txt：源允许 Move/Copy/Link/None 五种情况下，
                        盒子回给 OLE 的 Effect 必须落在允许集合里，5/5 才正常
DeskBox.exe --iconcmp out.png 文件1 文件2 …
                        同一个文件用四种取图策略各画一行（shell@48 / 256→44 /
                        256→48 / shell@44，1:1 加 2 倍），用来判断哪种最接近
                        资源管理器。行标签会打印在图上

配色自检（改颜色必做）：
  源码目录里有个 palcheck.py，把 5 套主题的 Plate/Text/Sub/accent 全部算一遍
  WCAG 对比度和 HSL 饱和度，任何一项不达标就报出来。判据：
    · 主文字 / 底板 >= 7:1，次要文字 >= 4.5:1
    · 每支 accent / 底板 >= 3.2:1（低于 3 在浅底上等于"没有颜色"）
    · accent 饱和度 <= 78%（纯霓虹 S=100%，刺眼且廉价）
  跑法：python palcheck.py
DeskBox.exe --toggle    只把"显示桌面"状态翻回去就退出（测试收尾用），
                        结果写 toggle-report.txt
